# 产品范围与当前决定

作者：Ray Zhang（Ray）。

日期：2026-11-13（Asia/Taipei）。状态：产品方向已记录，首轮基础已有本地与 Ray 分项实现，2026-11-13 常驻与 Starferry 合并计划已补充，完整功能尚未验收。

用户已确定产品名 **Reach**；2026-11-13 指定配置命令为 `ryreach`，替代早期文档中的 `reach` 命令示意（现有开发源码仍为 `reach`，旧名是否保留兼容别名在 D03/D05 确定）。作者完整名为 **Ray Zhang**，简写为 **Ray**；命名空间为 `RY`。

## 要解决的问题

本地 Codex 等 Agent 掌握源码，需要获取客户现场信息并操作现场环境，完成分析、修复和验证。Reach 提供通用远程能力和组织侧管理服务，既可以与业务产品关联，也可以独立使用。

QSpin 是可选工具来源。LabSlot 是可选管理入口和身份来源。两者均不是远端安装、基础连接或通用工具的硬依赖。

完全控制描述配对后的产品行为，具体操作仍通过实际操作系统会话和工具接口执行。Windows 服务安装可能触发系统自身的 UAC；不因此增加产品引导页、权限模式或功能审批步骤。

安装、配对和运行记录应清楚显示真实状态。取消、断线或结果未知不能被记录成执行成功，也不能通过自动重放动作掩盖状态。


## 2026-11-13 新增需求与验收条件

以下编号供架构和任务引用；来自[本轮用户决定及修正](knowledge/product-decisions.md#常驻服务与-starferry-合并2026-11-13)。编号表示需求，不表示已经实现。

<a id="req-01"></a>
### REQ-01 Starferry 功能归入 Reach

Reach 应接入现有 Starferry 的连接能力，支持 SSH 访问、UDP 直连和中转回退。验收条件：

1. 从 Reach 控制入口访问已配对目标，分别取得真实 SSH 命令结果和所选网络路径。
2. 禁止直连或直连不可用时可中转；已尝试的操作不因链路切换自动重放。
3. 旧 Starferry 的一次性会话与 Reach 常驻身份分别处理，不把旧程序或测试直接当作 Reach 交付。

<a id="req-02"></a>
### REQ-02 离线 OpenSSH 随包与按需启用

依据[11 月 24 日产品决定](knowledge/product-decisions.md#worker-agent-desk-20261124)，默认 Windows 包必装 Worker 和 Agent，离线 OpenSSH 随包交付。启用时复用已有配置、主机密钥和授权。以下验收待执行。

1. 干净 Windows 在 OpenSSH 未启用时完成安装，随后配对、上线并执行一项真实 Agent 任务，取得回执。
2. 从已配对的控制端通过 Agent 调用受管启用流程，核对目标机端口归属、可信主机密钥、登录和操作输出。启用失败时显示原因，原 Worker 与 Agent 在线和可执行。
3. 已有 OpenSSH 路径保留原配置、主机密钥和已有授权。撤销配对或卸载只处理 Reach 管理的授权。

<a id="req-03"></a>
### REQ-03 目标机服务常驻

Reach 应以独立后台系统服务运行，安装身份、配对关系和配置不依赖配置终端或 QSpin 进程。验收条件：

1. 关闭 `ryreach` 终端或退出业务产品后，Reach 服务和远程支持通道仍可用。
2. 服务重启后沿用原安装身份和有效配置，查回原操作记录，不重放效果未知的操作。
3. 服务等待首次配置、等待配对、离线和已连接状态可区分。系统服务启动成功与桌面实际可操作分别验收。

<a id="req-04"></a>
### REQ-04 分钟级心跳、远程配置与断网退避

Reach 应定时报告状态，心跳间隔为分钟级并可远程调整；网络不可用时执行有上限的退避规则。验收条件：

1. 服务端可查询最近心跳时间、有效间隔和实际生效的配置版本，不能把配置已下发当作已生效。
2. 受控断网期间服务仍运行，重连频率遵守退避上限；恢复后自动连接并恢复心跳。
3. 心跳用于状态报告，即时命令使用控制连接；不把心跳周期当作命令必须等待的轮询周期。
4. 网络错误、认证失败、配对撤销与无效配置分别报告；退避只重建连接，不重发未知操作。

<a id="req-05"></a>
### REQ-05 首次服务器地址与 ryreach 配置命令

安装应将 `ryreach` 注册到 PATH。尚未配置时，首次交互启动应输入服务器服务地址；以后应能通过同一命令修改并查询实际配置。验收条件：

1. 未配置的系统服务保持运行并报告“等待初始化”，不能阻塞在标准输入；首次输入由交互 CLI 承担。
2. 地址已由第三方安装器预配置时不重复询问；地址输入本身不替代登录或配对。
3. 地址和心跳等配置更新能查询保存值、生效值与失败原因；更换地址不将旧服务器凭据发送给新服务器。
4. 错误地址、TLS 错误、配置回执丢失和离线修改有明确结果或待应用状态，不能误报成功。

<a id="req-06"></a>
### REQ-06 独立交付与通用安装配置入口

Reach 应无需 QSpin 即可安装、配置和使用，并提供第三方安装器可调用的通用安装及配置入口。验收条件：

1. 独立安装后可经 `ryreach` 完成地址配置、配对和后台支持。
2. 受控第三方安装器可预配置地址并复用同一 Reach 安装；重复调用不产生第二套身份或服务。
3. 业务产品退出或卸载不会直接删除仍在使用的 Reach 服务、配置、收据或其他产品关联。

QSpin 将来默认安装 Reach 及配置服务器地址的工作归 QSpin 项目。本轮不设计或实施 QSpin 网关接入、产品托管子进程、进程内嵌入或 QSpin 安装器改造；这里仅定义通用合同。
## 当前架构建议

以下是待评审的组织方式，不是已经实现或全部定案的架构：

- `service`：注册、配对、连接中转、任务事件和收据；需要时接入组织模型服务。
- `node`：客户机 Host、系统服务、工具后端及按需桌面会话接入。
- `controller`：提供本地 MCP 和 CLI，两种入口共享连接逻辑。
- `admin`：Agent、连接、配对和运行记录页面，可由外部系统挂载。
- 可选 `Reach Desk` 扩展：云端聊天界面、对话历史及云端 Agent Host；通过 Reach 的公共控制合同调用设备，不再独立管理设备连接。

本地 Agent 可以逐次调用远端工具，也可以委托远端完成子任务。需要远端循环时复用 ARA Lite Core 与 Harness；远端循环的位置和模型推理服务的位置分别描述。

当前部署面向 Ray 工作台，Reach 持有自身账户、数据和服务生命周期，已通过服务端身份桥接复用 Ray 登录。首版不接 LabSlot。云端平台扩展仍在设计，Ray 可以选择启用；默认发行不加载聊天路由、聊天资源、云端模型进程或聊天数据存储，也不要求模型配置。

启用扩展后，可以不连接设备而直接与云端模型对话，也可以明确选择已配对的 Reach 设备执行任务。扩展范围和旧 HandWave 迁移条件见[扩展设计](platform-extension.md)。此处的选择用于确定执行位置，不是权限模式。

产品安装器可以调用同一基础安装包并预配置服务地址。Reach 保持独立进程和生命周期；外部安装器的具体接线由各产品负责。可选产品 API/MCP 登记与安装软件包是两种行为，均不要求把 Reach 运行时嵌入产品。

## 命令示意

2026-11-13 指定配置命令名为 `ryreach`，子命令及参数为讨论示意，须在 D03/D05 确定后实现（当前开发版源码仍使用 `reach`，提供 `pair --server --code`、前台 `run` 和停机/IPC `status`；旧 `reach` 是否保留兼容别名待定）：

```powershell
ryreach

```
