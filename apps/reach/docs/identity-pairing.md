# 身份与配对

作者：Ray Zhang（Ray）。日期：2026-11-02。状态：实施合同；前台配对与 Ray 统一登录已有运行证据，Windows 服务宿主/IPC 已实现，普通进程验证与正式安装验收分别记录。

## 账户和控制端

首版独立账户由服务启动时的一次性 bootstrap 配置初始化；已有账户存在时不覆盖密码。密码使用带随机盐的 scrypt 保存。原生及独立登录会话凭据使用随机 256-bit 值，只保存 SHA-256，默认十二小时有效；退出登录使该会话失效。Ray 浏览器会话的稳定派生与平台绑定单列于下文。

浏览器使用 HttpOnly、Secure、SameSite=Strict Cookie；变更请求还需匹配 public origin 和当前会话 CSRF token。控制器使用 Bearer session token，存入受保护的本地配置，不进入 MCP 工具参数。未认证的代理请求不会因为来自环回地址就被视为已登录。

登录/配对限流按实际客户端地址分桶。只有精确配置的代理连接地址可提供 X-Reach-Client-IP，入口必须覆盖此头而不透传客户端值；缺失或非 IP 拒绝。其他连接忽略该头。上线时需核验两个公网来源通过同一入口仍分属不同额度。

同一账户可绑定多台 Node，并可建立多个控制器会话。当前不引入角色权限或逐工具审批。不同账户的设备、操作、结果和附件均按已认证账户隔离。

## 首次配对

1. 控制端登录，生成账户绑定的一次性配对码，有效期十分钟。
2. Node 在发请求前持久保存 installationId、随机 256-bit installationSecret、attemptId 和本次配对输入。Windows 安装版通过服务 IPC 完成该步骤。
3. Node 经 HTTPS 发送配对输入。服务在同一事务内检查配对码、消费配对码、建立 Node/账户绑定和 epoch、保存尝试摘要。
4. 服务只保存安装凭据 SHA-256。响应含 nodeId/epoch/revoked；Node 不依赖响应接收新秘密。
5. 响应丢失时使用同一 attemptId 和完全相同输入重试，返回原接受收据；同 ID 改内容拒绝。相同 epoch 已被解绑时返回 revoked=true，恢复原凭据的持有关系，但不重新激活绑定；之后可凭新配对码重配。epoch 已被替换则拒绝旧尝试。

Windows 常驻宿主持有唯一账本，配对命令经本机认证管道到达。生产绑定主体在安装时确定，客户端发送配对码前核验 SCM 与管道进程；设备执行期间的重配返回 busy。详见[安装合同](installation-update.md)。

网络配对成功后，身份和以输入摘要标识的本机配对收据同事务保存。IPC 客户端丢失答复后可以重试原输入，返回 `pairingReceipt` 和当前绑定；旧 epoch 收据不代表当前仍绑定在旧 epoch。pending 未结算时不接受另一输入，也不恢复旧身份领取。

Node 在保存新尝试前校验 code/name。网络故障或不明确的响应保留原尝试；invalid_pairing_code、invalid_request、operations_unsettled、installation_owned 这些明确未接纳的错误允许释放 pending，原安装身份不变。

安装凭据是 Node 对服务的传输身份，必须保密、使用有效 HTTPS、不跟随跨源重定向。公网明文连接和无效证书应在 Node 入场时拒绝。短配对码不作为长期身份。此实现使用随机对称安装凭据，不声称已有 Ed25519 挑战认证。

## 再次配对和解绑

再次配对需新的配对码和原安装凭据。存在已排队、运行或结果未知的操作时先结算原操作；服务不悄悄创建第二套安装身份。成功替换时提升 epoch、轮换凭据和账户绑定，旧凭据失效。

Node 还检查本地未 ACK 的 outbox 和 received/running 记录。先以原身份 run，恢复未知结果并补传原回执，再换配对。即使服务已人工对账，也不能跳过本地恢复。已上传的本地 unknown 是否已结算以服务对账记录为准。跨服务迁移另行设计，当前不允许用新服务器地址覆盖原绑定。

解绑立即停止新任务投递，未领取任务成为取消；已经派发的操作标记投递不确定并请求取消。原凭据只保留查询原操作取消状态、补传原回执的能力，不能再领取新操作。撤销不表示已执行效果被撤销。

损坏或丢失安装凭据时不得自动重建同名设备来掩盖原操作。恢复流程需核对旧安装和收据，具体修复命令随安装/更新模块交付。

## Ray 统一登录与延期的 LabSlot

用户要求“Ray平台登录后，不用再次登录reach了”。Ray 部署通过已验证的平台会话和专用签名桥接到固定 Reach 账户；Reach 不获取 Ray OTP 种子。声明包含用途、受众、nonce、签发和到期时间，重复换票被持久拒绝，普通页面参数不能表达身份。

同一平台会话的 Reach token 由专用密钥、固定账户和平台会话哈希稳定派生。并发首次开页也复用同一有效 Reach 会话及 CSRF，避免新标签使旧页写请求失效。每次浏览器 API 请求重新核对 Ray 登录及绑定，验证用途的声明不能创建会话。SSO token 不能改作原生 Bearer；原生控制器和 Node 的登录保持独立。

页面退出走 Ray 工作区退出；Reach Cookie 失效时提供回到入口重连，不要求第二次 Reach 密码，也不重放原操作。两库不是联合事务，失败拒绝并允许下次根页恢复。完整接线以[系统集成](integrations.md)为准，实际范围见[统一登录证据](evidence/ray-sso-20261102.md)。LabSlot 接入继续延期。
