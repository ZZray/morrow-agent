## 每份设计解决什么

| 文档 | 应回答的问题 | 不承担的内容 |
|---|---|---|
| `project-plan.md` | 首版目标、组件职责、阶段与里程碑、依赖和推进顺序 | 专项接口字段和实时任务状态 |
| `task-checklist.md` | 每项任务的交付物、前置、验收与完成证据 | 另行定义产品行为或接口合同 |
| `architecture.md` | 本地 Agent、服务、Node、Lite/Harness 与工具后端怎样协作；什么数据归谁；哪些组件同进程或独立部署 | 详细 API 字段、完整功能实现计划 |
| `identity-pairing.md` | 如何独立登录；如何建立安装与控制端身份；首次/再次配对、解绑、多端连接如何处理 | Auto/Full 模式、工具权限开关、角色权限表或逐次审批 |
| `installation-update.md` | 双击安装的实际步骤、服务启动、PATH、生效窗口；已有安装、更新、共享基础包、卸载如何处理 | 产品业务工具的实现细节 |
| `tools-tasks.md` | 本地 MCP/CLI 提供什么；能力说明与技能怎样传递；单次工具和委托任务怎样返回状态与证据 | 重新实现 Core 循环、复制全部产品 API |
| `integrations.md` | Ray 工作台怎样增加独立 Reach 入口；产品如何登记能力；资产资料怎样引用原数据源；延期的 LabSlot 接入边界 | 复制维护外部系统的机器主数据 |
| `platform-extension.md` | HandWave 如何可选装配，云端对话怎样复用 Reach，旧入口与历史怎样迁移 | 把扩展加入默认包、复制 Agent 循环或以文档宣布已退役 |
| `acceptance.md` | 什么观察能证明独立使用、完全控制、安装配对和跨产品集成可用；哪些层尚未验证 | 用文档、编译或模拟测试替代真实产品验收 |
| `reuse-map.md` | 固定来源版本、现有行为、依赖、许可、可保留测试、迁移成本和差异 | 直接把历史设计或旧测试视为新产品交付 |

## 专项文档推进顺序

1. 按本文维护文档职责和目录组织。
2. 维护架构与复用调查：记录已选技术和固定来源，保留桌面后端等尚未验证的边界。
3. 写身份配对与安装更新：把“登录后直接进入、双击安装、命令配对、完全控制”连成用户流程。
4. 写工具任务与系统集成：确定可执行合同，复用已存在的 Lite/Harness/MCP 机制。
5. 写验收场景，细化已有任务清单；每个实施点引用对应设计和验收条目。当前 52 项是计划划分，专项合同明确后可以保留 ID 继续细化。

范围清楚的小问题直接修正文档；只有影响职责、兼容性或长期维护的重要选择才新增 ADR，不为每个细节建立审批流程。

## 文档状态和更新

- **讨论稿**：当前建议、备选项和待回答的问题，不表示已经决定。
- **已确定的设计**：有明确来源的决定；仍不表示代码已经实现。
- **实现状态**：记录实际代码版本和与设计的差异。
- **验证状态**：引用实际运行环境、命令、结果及覆盖缺口。

用户更正优先更新产品范围和知识来源，再同步受影响的专项设计。过时建议保留必要的变更原因，不让旧方案继续作为当前要求。

当前 v1 合同权威来源为 [protocol.ts](../src/contracts/protocol.ts) 的 Zod schema，`protocolDocument()` 生成机器可读合同。API 文档、示例和语言类型引用或生成自该来源；Rust 映射通过合同测试核对，避免多套字段定义独立漂移。

项目计划与任务清单以 Markdown 为持续维护来源。`plans/` 下的 JSON 和 HTML 是带日期的阅读快照；状态变化先更新任务清单，再按需要刷新快照并注明日期。

## 知识库与 Agent 经验的区别

项目知识库记录开发本产品时需要保留的决定、限制和经验，不直接充当远端 Agent 的自动记忆。

远端任务上下文、可复用技能和持久知识属于运行时功能，需要在 `tools-tasks.md` 中分别定义来源、作用域、验证及晋升方式。一次任务完成不自动修改组织技能或项目知识。

## 文档检查与后续验收

当前文档检查：相对链接可解析、术语一致、已确认与待讨论分开、命令示意不冒充实现、没有遗留的控制模式或权限中心设计。

后续验收应覆盖：无产品关联时的安装配对与操作；独立登录与 Ray 工作台入口；命令二次配对；多个产品共享 Agent；安装和更新后的服务状态；工具与桌面真实操作；取消和断线后的实际结果。LabSlot 登录集成按 2026-11-02 用户修正延期，不是首版验收条件。具体测试步骤在相应设计完成后编写。
