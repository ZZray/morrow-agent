# Reach Desk 云端 Host 接入候选

作者：Ray Zhang（Ray）。日期：2026-11-03。范围：X01/X02 与 R01 的云端装配部分。完整基础 0/52、Reach Desk 0/5；未上线，尚无新聊天界面或设备委托。

Reach Desk 已通过真实 Rust JSONL → Harness → Lite Core 接通持久对话。受控模型下，同一原生 Session 连续回答、流式传递、重复提交、取消及崩溃后查询原记录已有进程证据。两次真实模型尝试均未获得回答，因此不能验收真实云端对话。

## 实现与边界

新代码在 `platform/src/`，后续维护仍在 Reach 内部。`platform/src/main.ts` 是选装入口，基础 `src/service/main.ts` 不导入平台实现。基础服务只持有可选接口，身份、Cookie、CSRF 和退出仍由 Reach 处理；没有第二套设备、配对或账户表。关闭扩展不会读取模型凭据、创建聊天库或启动 sidecar。

Desk 事务先固定用户、对话、消息 ID、输入摘要、Task/Run ID，再启动共享客户端。同 ID 同内容返回原记录，内容变化冲突；同对话只允许一个活跃任务。正常下一条消息沿用原生 Session/key，只提交新消息。状态目录有进程租约；进程死亡后的未完成记录保留原 ID，标 unknown 并阻止原 Session 继续，不重新投递。

每条消息首轮采用 `max_runs=1`。Host 不提供本地、设备或 MCP 工具；Core 自带八个 Session 工具仍存在，覆盖进度、原文/历史读取及候选经验，不应描述成“模型没有任何工具”。模型地址、程序、目录和预算来自部署配置，凭据只交共享客户端的固定子环境。verifier 保存原候选 basis 和正文摘要，只证明回复接收/保存，**不验收内容事实或业务任务**；公共 `task_accepted=false` 保留。最终状态须同时核对客户端 delivery、回调结算、Harness outcome 和 fence。

JSONL v1 通知只有事件类型；正文读取适配固定 Harness 的 `run-1-admission.json` 与 `run-1-events.jsonl`。先确认完整 admission 与 Task/Run 身份，再增量读取完整 UTF-8/LF 帧、连续序号，限制帧和展示量；只转发 `text_delta`，完整 `text` 不重复拼接。终态正文来自客户端已核验候选。原件读取异常只说明展示流不可用，不能据 UI 流决定 Task 成功或重跑。

固定 rpi `8ec4626` 把增量累积到 64 bytes，或在下一个文本块到达时检查已过 40 ms，才发 TextDelta。没有独立 40 ms 定时器；短首段后上游沉默可能等到下一块或结束。最终测试用超过阈值的中文首段验证 EOF 前真实传递，不承诺逐 token 即时显示。

SSE 的发起连接断开后请求取消；同一登录会话的重复连接共享计数，其他登录的观察者不能维持原执行授权。正常终态关闭不追加取消。退出仅取消原登录会话启动的任务，登录到期持续重查。Ray 已有退出/到期撤销代理连接的源码通道，但**本轮未做跨 Ray 代理的长流实测**。

停止或崩溃后若 Harness 仍有 fence，对话保持需处理状态，历史可读，可显式新建对话。当前不能在原对话停止后直接继续；还需共享 Harness 的结算/释放合同。没有删 fence、换 Session 或重放聊天历史来绕过它。

## 失败、复核修补和真实模型

- 受控 r1 错把 Core 来源摘要中出现的原句计作重复用户消息。已直接核原 HTTP body，改为精确用户消息计数，保留失败日志。
- 受控 r2 的“没有任何 tools”断言失败；真实 wire 含八个 Session 工具。改为核精确工具名，保留外部执行工具为零的合同。
- r3 虽6/6通过，独立复核查出 fixture 使用最后一个 user（实际是预算提示）识别 wait，导致挂起分支未执行；小文本增量也在末尾合并，不能证明 EOF 前出字。r4 修正为精确业务消息识别及因果门禁；r3 不再充当这两个场景的验收证据。
- 独立复核发现并修补 SSE 关闭与 DB 生命周期竞态、半写 admission、响应先关闭仍可能启动，以及双信号重复关闭。最终受影响故障用例均有上述记录。
