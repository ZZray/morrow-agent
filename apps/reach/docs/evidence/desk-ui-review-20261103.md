## 已闭合的审查问题

| Before | After | Why |
|---|---|---|
| 新对话创建等待时，输入事件可能重新启用发送，造成重复创建 | 用独立 admission 对象持有提交锁，旧 finally 不能释放新锁 | 同一次用户提交只建立一次原请求 |
| 创建期间输入的后续草稿只留在 new，切换回来后丢失归属 | 仅在原 view 仍匹配时迁入新对话 ID；浏览器实际切走再返回核验 | 保留未发送输入及其所属对话 |
| 断流查询仍为 running 后失去观察，页面可能一直等待 | 查询原消息，最多自动 GET 恢复一次；仍断开则提供原记录查询 | 恢复读取不重新 POST 或执行模型请求 |
| 较早查询可能覆盖已完成的较新消息 | Turn revision 和对象身份同时守卫响应 | 原完成正文和终态不回退 |
| 登录或恢复身份后，历史失败写入已移除的登录 DOM | 保留已进入的页面，显示错误并提供刷新历史 | 读取失败不冒充认证失败或无声消失 |
| 窄屏隐藏唯一账户/退出区域 | 保留账户与退出，390px 实际截图和点击均检查 | 小屏仍可正常退出并清空页面内容 |
| 旧终态及旧查询的 blocked=false 能覆盖当前阻塞 | open、query 与 settled 均保留已经观察到的 blocked=true | 历史收据不能解除较新的 Session 阻塞 |

当前服务只支持 blocked 从 0 到 1，因此单调处理与服务合同一致；未来增加真实结算释放时，应同步设计版本化状态更新，不能沿用此规则宣称已实现恢复。
