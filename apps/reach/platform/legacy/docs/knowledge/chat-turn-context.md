# 聊天轮次上下文冻结

## 不变量

每条新用户消息落盘时，必须与当时可见的消息数量原子记录；初始响应和工具续接都使用该冻结边界，不得重新选择“最后一条用户消息”。

构建上游历史时：

1. 旧格式历史保持原线性语义；
2. 新格式只继承提交边界内已经产生最终 assistant 消息的完整轮次；
3. 当前轮的 assistant/tool 消息按 `turn_id` 单独追加；
4. 浏览器只回传 `turn_id`，技能正文始终从 hub 已落盘的用户消息快照读取。

## 为什么

同一会话可能被多个标签页同时发送。若按 JSONL 的物理末尾选择用户消息或简单截取前缀，会出现两类错误：早请求读取晚请求的技能；晚请求带入早请求的 tool call，却漏掉稍后落盘的 tool result，形成非法上游历史。

## 回归场景

`TestChatTurnUsesRequestedSkillSnapshot` 固定覆盖：

- A 尚未完成工具调用时提交 B，B 不得看到 A；
- A 续接时不得看到 B；
- A/B 都完成后提交 C，C 必须同时继承两条完整历史；
- 无效 `turn_id` 的续接不得污染会话文件。
